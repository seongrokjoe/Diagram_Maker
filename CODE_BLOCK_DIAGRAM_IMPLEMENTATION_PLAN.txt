추가 승인 계획: CODE_DIAGRAM_ACCURACY_PLAN.md (2026-09-11, 코드/Git 다섯 형식·Git State·실행 사실 기반 의미 계획)
확정일: 2026-09-08
기준: 현재 작업본의 자연어/Git 다이어그램, semantic-plan-v2, source-graph-v8

1. 목표와 확정된 사용자 경험

사용자가 코드 몇 개를 붙여넣으면 코드의 역할과 호출 문맥을 분석하여 이해하기 쉬운
다이어그램을 생성한다. 코드를 문장별 노드로 그대로 옮기거나 함수명만 나열하지 않고,
핵심 동작 요약 → 상세 흐름 → 원본 코드 근거를 탐색하도록 한다.

- 기존 자연어/Git 탭 옆에 '코드 블럭 다이어그램' 탭을 추가한다. Git 등록은 불필요하다.
- 블럭마다 C/C++ 또는 C#을 선택한다. 제목, 코드, 선택적 설명을 입력하고 추가/삭제/
  순서 변경을 제공한다. 첫 언어는 C/C++, 다음 블럭은 직전 언어를 따른다.
- 파일/클래스/함수뿐 아니라 함수 내부 일부 구문도 지원한다. 없는 문맥은 발명하지 않는다.
- 근거 있는 호출/타입 관계로 그룹을 자동 제안하고 사용자가 합치기/나누기/이동/독립
  그룹을 지정한다. 하나의 블럭은 하나의 그룹에 속하며 사용자 그룹을 우선한다.
- 그룹별 독립 결과를 생성한다. 그룹 간 호출은 병합을 제안하며 자동 병합하지 않는다.
- 같은 그룹이라는 이유만으로 관계를 만들지 않는다. 무관한 블럭은 독립 항목으로 둔다.
- Flow, Sequence, Class, State, 코드 관계도 5종을 제공한다. 기본은 그룹마다 적합한
  1종 자동 추천, 종류별 최대 하나씩 총 5개를 선택할 수 있다.
- 코드/결과/그룹/관계 답변/생성 이력을 소유자별로 영구 저장하고 재조회/수정/재생성한다.
- 기존 미리보기, 확대, 상세 페이지, 편집, 근거 탐색, 다운로드를 재사용한다.
- 기본 흐름: 코드 입력 → 만들기 → 분석/그룹 제안 → 필요한 경우만 관계 질문 → 결과.
  명확한 입력은 검토 버튼 없이 자동으로 결과까지 진행한다.

2. 분석과 생성

2.1 코드 사실 추출
- 기존 Roslyn(C#), Tree-sitter(C/C++) 분석기를 재사용한다. 가짜 Git 비교/커밋은 만들지
  않는다. 입력 스냅샷, 심벌, 호출, 제어 흐름, 타입 관계는 Git 중립 계약으로 분리한다.
- 공통 구문 분석을 분리하되 기존 Git 서비스/공개 API/변경 의미는 어댑터로 보존한다.
- C#은 파일/클래스 멤버/함수 구문을 구별하고 필요한 분석용 클래스/함수 보정을 한다.
  합성 이름/코드는 결과에 노출하지 않고 실제 타입으로 취급하지 않는다.
- C/C++ 전용 stdin 작업자가 parseCppFile/resolveCppCalls를 재사용하고 함수 구문을
  보정한다. Git/사용자 파일 경로/헤더/외부 자료를 읽거나 실행하지 않는다.
- 보정 전후 위치 매핑을 유지한다. 근거는 블럭 ID, 스냅샷, 코드 해시, 원본 줄/위치로
  식별한다. UTF-8 바이트와 C#/JS 문자열 위치를 정확히 변환한다.
- 비어 있지 않은 코드가 분석 결과 없이 끝나면 성공으로 처리하지 않는다. 부분 복구와
  누락 범위를 알린다. 해석 불가 구문은 해당 범위 제한으로 표시한다.
- 오버로드, 수신 객체, 네임스페이스, 선언 범위를 고려한다. 동명 심벌/중복 코드/파일
  지역 함수/분리된 문맥을 임의로 합치거나 이름만으로 호출을 확정하지 않는다.
- 언어 혼합 그룹을 허용한다. 언어 간 호출은 명백한 상호운용 근거 또는 사용자 확인만
  반영한다. 컴파일/빌드/복원/사용자 코드 실행/외부 파일 수집은 하지 않는다.

2.2 그룹과 관계 확인
- 확인된 호출/타입 관계의 연결 성분으로 초기 그룹을 제안한다. LLM은 역할/그룹 제목과
  기능상 관련 그룹 제안을 보완할 수 있으나 같은 역할이 호출의 증거는 아니다.
- 결과에 영향을 주는 모호한 호출 대상, 콜백/인터페이스/간접 호출, 코드 밖의 연결만
  질문한다. 관련 블럭/코드 위치/후보/질문 이유를 표시한다.
- 실행당 최대 5개를 한 차례 묶어 질문한다. 연결 없음/모르겠음/나머지 건너뛰기를
  제공한다. 답변 후 무한 재질문하지 않고 미확인 부분을 결과에 남긴다.
- 사용자는 출발/도착 블럭 또는 심벌, 방향, 호출/데이터 전달/의존, 설명으로 관계를
  추가할 수 있다. 코드 근거와 사용자 제공 관계를 별개 출처로 저장한다.
- 사용자 관계에는 '사용자 제공' 연결선 표시를 붙인다. 점선만으로 출처를 구별하지
  않는다. 관계 확인이 실행 위치/분기/순서를 확인한 것으로 확대되지 않게 한다.
- 위치 미확인 호출은 코드 관계도 또는 별도 사용자 제공 시나리오에 표현한다.
- 그룹을 넘는 관계를 한 그림에 넣으려면 사용자가 병합한다.
- 코드 변경 시 해당 질문 답변/관계 근거를 재검토하며 오래된 답변을 거부한다.

2.3 의미 중심 생성
- 파이프라인: 사실 추출 → 블럭 이해 → 그룹 이해 → 종류 선택 → 의미 단계 계획 →
  사실/제어/의미 검증 → 안전한 Mermaid 생성.
- LLM에 실제 코드, 인수/대입/조건/호출 근거와 출처가 구별된 사용자 관계를 전달한다.
- 준비/핵심 처리/검증/오류 처리로 요약한다. CSV 예: 입력 준비 → 보고서 생성 →
  헤더와 결과 검증. 각 의미 단계는 실제 코드 근거와 상세 보기를 제공한다.
- 핵심 호출/조건/반복/조기 반환/오류 경로를 보존한다. 다른 제어 경계를 무조건 실행
  단계로 합치거나 독립 함수 사이에 실행 순서를 만들지 않는다.
- 모든 요약 노드는 원본 사실 ID를 유지한다. 연결은 확인된 관계 또는 사용자 설명만
  사용한다. 요약에서도 실제 블럭 간 호출을 유지한다. 기존 문서 빌더의 메서드 요약
  노드 + 빈 연결선 방식을 그대로 적용하지 않는다.
- LLM은 구조화 JSON만 반환하고, 검증된 IR을 기존 MermaidCompiler로 컴파일한다.
- 정적 검증으로 참조/방향/출처/제어 경계/근거 누락을 확인하고 LLM 의미 검토를 한다.
  의미 계획 수정은 최초 생성 뒤 최대 1회. 실패 시 정적 결과를 '의미 설명 미완료'로
  표시하며 의미 생성 성공으로 취급하지 않는다.
- 입력 제한은 함수/제어 문맥 단위 분할로 처리하고 조용히 자르지 않는다.

종류별 기준:
Flow: 처리 단계/조건/반복/종료. 독립 함수 사이의 허위 순서를 금지한다.
Sequence: 확인된 호출 순서/분기. 독립 진입점은 별도 시나리오로 분리한다.
Class: 실제 클래스/구조체/인터페이스와 타입 관계. 분석용 합성 타입은 제외한다.
State: 동일 상태 변수의 조건/분기/대입으로 확인되는 전이. enum/이름만으로 만들지
  않는다. 초기/종료 상태도 근거가 있어야 한다. 기존 Git의 State 제외 경로와 별도로
  코드 블럭용 상태 전이 추출기를 구현한다.
코드 관계도: 함수/구현 역할과 호출/의존/데이터 전달. Git 변경 강조는 사용하지 않는다.

자동 종류는 생성 가능한 종류 안에서 LLM이 추천한다. 실패 시 명시적 상태 전이 →
블럭 간 호출 Sequence → Flow → Class → 코드 관계도 순서로 가능한 것을 선택한다.
없으면 필요한 입력 보완을 안내한다. 기본 프리셋은 balanced이며 Thinking은 꺼져 있다.

3. 구조, 계약, API, 저장

- UI: CodeBlockWorkspace를 분리하고 DiagramEditor/PresetPicker/근거/페이지를 재사용.
- 서버: CodeBlockAnalyzer, 그룹/질문 서비스, CodeBlockProjectionService, 생성 처리기,
  백그라운드 작업자. 구문/LLM/검증/렌더링 공통 기능은 재사용하되 Git 기능은 보존한다.
- UnderstandCodeBlocksAsync/PlanCodeBlockDiagramAsync 등 별도의 코드 동작 프롬프트를
  사용한다. Git 변경 전후 프롬프트를 그대로 사용하지 않는다.
- 기존 프리셋 ID/스타일을 사용하고 새 화면의 '변경 지점/변경 구현' 문구는 중립화한다.

주요 계약:
CodeBlockInput: 안정적 ID, cpp/csharp, 제목, 코드, 선택 설명.
CodeBlockGroupSelection: ID/제목, 블럭 ID 목록, 출력 형식 선택.
CodeBlockRelation: 양 끝 블럭/심벌, 종류/방향, code/user 출처, 근거 또는 설명.
CodeBlockQuestion: 안정적 ID, 코드 근거, 후보, 답변 상태.
CodeBlockEvidence: 블럭 ID, 입력 스냅샷, 코드 해시, 원본 줄/위치.
CodeBlockWorkspace: 소유자, 현재 입력/그룹 설정, 수정 번호.
CodeBlockRun: 고정 입력 스냅샷, 그룹/관계/답변, 상태, 결과/페이지/근거/메타데이터.

공통 모델 변경은 역호환 선택 필드로 한다:
- DiagramEdge.RelationOrigin(code/user).
- DiagramExplanation.Behaviors(변경 설명과 별개인 코드 동작 설명).
- DiagramRevisionService를 SourceKind=code-block으로 재사용한다. 편집 출처를 보존하고
  수동 추가/관계 변경을 코드 검증으로 위장하지 않는다. 구형 결과는 계속 읽힌다.

API 접두사 /api/v1:
POST/GET /code-block-workspaces
GET/PUT/DELETE /code-block-workspaces/{id}
POST/GET /code-block-workspaces/{id}/runs
GET /code-block-runs/{runId}
POST /code-block-runs/{runId}/answers
POST /code-block-runs/{runId}/cancel
GET /code-block-runs/{runId}/groups/{groupId}/views/{viewId}/pages/{pageId}
GET /code-block-runs/{runId}/evidence/{evidenceId}
POST (위 페이지 경로)/edit-preview
POST (위 페이지 경로)/edits

- 저장/생성은 expectedRevision, 답변은 입력/실행 수정 번호를 검증한다. 오래된 답변,
  중복 실행, 편집 충돌은 409. 생성은 202 + 실행 ID.
- 상태: Queued → Indexing → NeedsClarification 또는 Generating → Completed/Partial/
  Failed/Cancelled. 질문 대기도 영구 저장하여 브라우저/서버 재시작 후 이어간다.
- 목록/상태에는 코드 원문/전체 페이지를 보내지 않는다. 상세/근거는 필요 시 조회한다.
- IAppStore 및 InMemory/LocalFile/Postgres 모두 확장한다. LocalFile은 작업/실행별
  파일과 원자 교체. Postgres는 소유자/상태/수정 번호/JSON 테이블과 인덱스를 추가한다.
- 과거 결과 근거는 과거 스냅샷을 가리킨다. 삭제는 관련 원문/실행/편집 이력을 포함한다.
- 재사용 키: 소유자, 코드/언어/그룹/답변 해시, 분석기/프롬프트 버전, 모델 설정,
  종류/프리셋/스타일. 화면 전환/근거 조회는 LLM을 호출하지 않는다.
- 선택 결과만 재생성한다. 실패 시 이전 성공 결과를 최신 실패 표시와 함께 유지한다.
- 저장소 lease/갱신을 사용하고 취소/재시작/입력 변경 후 오래된 결과 쓰기를 방지한다.
- 소유자는 인증 문맥에서 구한다. 모든 조회/근거/편집/삭제에 소유자 검증을 적용한다.
- 코드 원문 저장 정책을 SECURITY.md에 명시한다. 본문/프롬프트/응답 로그 금지,
  승인된 내부 LLM, 기존 마스킹, 신뢰할 수 없는 코드/주석/LLM 응답 정책을 유지한다.
- codex-sample 모드는 새 API 전체 및 작업자 실행을 차단한다.
- 전용 작업자 파일을 Windows 오프라인 패키징 복사 목록에 포함한다.

4. 검증과 완료 조건

- 입력: C 함수, C++ 선언/구현, C# 클래스/메서드/조각, 잘린 코드, 빈 분석 결과,
  한글/CRLF/UTF-8 위치 매핑.
- 관계: 실제 블럭 호출, 무관한 블럭 같은 그룹, 동명/오버로드/간접 호출, 중복, 언어 혼합.
- 질문: 자동 생성, 조건부 질문, 답변/건너뛰기/연결 없음, 사용자 관계 표시, 병합 선택,
  입력 변경 후 오래된 답변 거부.
- 의미: 준비/핵심/검증 구분, 인수/조건/반복/반환/오류 보존, 허위 순서/관계 방지.
- 출력: 5종 Mermaid, State 근거/미근거, 가용성 이유, 요약/상세 연결/근거 보존.
- 저장/운영: 3개 저장소, 재시작/질문 복원, 취소/충돌, 과거 결과, 선택 재생성, 소유자 ACL.
- 보안: 주석 지시문/HTML/Mermaid 삽입/경로/마스킹/본문 로그/sample API 차단.
- 화면: 블럭/언어/탭 초안/그룹/질문/새로고침/근거/편집/다운로드.
- 전체 검증: powershell -ExecutionPolicy Bypass -File .\scripts\verify.ps1
- 새 API/UI 검증을 기존 검증에 통합하고 오프라인 패키지에서 새 화면/작업자를 확인한다.
- FakeVllm은 계약/실패 검증용이다. 별도로 승인된 내부 LLM에서 합성 C/C++/C# 사례를
  검토한다. 허위 관계 없음, 주요 동작/분기 보존, 모든 의미 단계의 근거 탐색이 완료 기준.

5. 구현 순서, 기본값, 인계

순서: (1) 계약/저장/ACL/API/작업 → (2) 파서 분리/조각/위치/호출/State →
(3) 그룹/질문/관계/무효화 → (4) 의미/종류/투영/검증/페이지/재생성 →
(5) UI/회귀 테스트/문서/패키징.

- 최대 20블럭, 블럭당 20,000자, 전체 100,000자. 설정으로 조정 가능.
- LLM 입력/시간 제한은 기존 설정을 따른다. 자동 무단 잘라내기 금지.
- 서버 저장은 '초안 저장' 또는 '만들기' 시 수행한다. 삭제 전까지 보존한다.
- v1은 직접 붙여넣기만 지원한다. 별도 파일 업로드를 추가하지 않는다.
- 기존 미커밋 변경은 사용자 작업이다. 기능 구현 전 전체 checkpoint를 커밋/푸시한다.
- 진행 및 재개 지점은 CODE_BLOCK_DIAGRAM_PROGRESS.md를 반드시 확인/갱신한다.
- 단계 완료와 중요한 실패/설계 보정/검증 결과를 기록한다. 중단 시 재개 명령과 다음 작업을
  남긴다. 구현 완료/실제 LLM 품질 검증/원격 푸시 여부를 사실대로 구분한다.
