Diagram Maker Windows x64 오프라인 설치
========================================

1. 함께 제공된 .sha256 파일과 ZIP의 SHA-256을 비교한다.

   certutil -hashfile DiagramMaker-0.1.0-offline.13-win-x64.zip SHA256

2. ZIP을 쓰기 가능한 로컬 폴더에 완전히 압축 해제한다.
   OneDrive 동기화 폴더보다 C:\Tools\DiagramMaker 같은 로컬 경로를 권장한다.

3. CMD에서 git --version을 실행한다.
   Git 변경 분석은 설치된 네이티브 Git을 우선 사용한다. Git이 없으면 fallback Worker로 동작하지만,
   대용량 pack 저장소와 C++ 프로젝트 인덱싱은 네이티브 Git이 필요하다.

4. configure-llm.cmd를 실행한다.
   생성되는 정책 파일에서 승인된 사내 정보만 설정한다.

   Endpoint      : /v1/chat/completions까지 포함한 전체 URL
   AllowedOrigin : scheme + host + port
   Model         : 승인된 모델명

5. start.cmd를 실행하고 CMD 창을 닫지 않는다.

6. 다른 CMD 창에서 아래 명령을 순서대로 실행한다.

   health-check.cmd
   test-llm.cmd

   이 시험은 고정된 합성 데이터만 사용하며 실제 저장소나 사용자 prompt를 보내지 않는다.

7. 브라우저에서 http://localhost:5080 을 연다.

8. Git 변경 분석은 다음 순서로 사용한다.

   - 저장소 관리에서 로컬 저장소를 등록한다.
   - 문자열 기반 사내 호출 API가 있으면 등록된 저장소의 간접 호출 규칙에 API명, 클래스/메서드 인자 번호와 필요한 변수 별칭을 저장한다.
   - Target 커밋을 선택한다. Base는 첫 번째 부모로 자동 선택된다.
   - 사전 분석 결과에서 표시할 변경 심볼을 체크하고 그룹을 조정한다.
   - 각 그룹에서 메서드 흐름도, 호출 시퀀스, 클래스 관계 또는 코드 관계도 형식과 샘플을 선택한 후 생성한다.
   - 결과 탭에서 SVG 또는 PNG로 다운로드한다.

9. 종료할 때 start.cmd가 실행 중인 CMD에서 Ctrl+C를 누른다.

이 패키지는 .NET SDK, Node.js/npm, 외부 CDN을 요구하지 않는다. Git 분석에는 PATH에서 실행 가능한
사내 승인 Git을 권장한다. LLM endpoint, prompt, Git diff, 모델 응답 원문은 기본 로그에 기록하지 않는다.
