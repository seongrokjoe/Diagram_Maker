internal.7 고정 합성 입력 측정

before.cpp와 after.cpp는 로컬 회귀와 같은 1,212줄·40함수·4클래스의 합성 입력이다.
사용자 코드 실행이나 빌드가 필요하지 않으며 사내 코드·서버 주소를 포함하지 않는다.

1. 코드 블럭 탭에서 before.cpp 전체를 C/C++ 블럭에 붙여 넣는다.
   새 작업에서 Flow만 선택해 3회, Flow/Class/코드 관계도 3종을 선택해 3회 측정한다.
   각 회차는 별도의 새 작업을 사용한다. 같은 작업 재생성은 캐시 시험으로 분리한다.
   Thinking OFF, balanced, 동일 모델·정책을 유지한다.
2. Git 시험은 승인된 비동기화 폴더의 시험 저장소에 Example.cpp로 before.cpp를 커밋한 뒤
   같은 파일을 after.cpp로 교체해 다음 커밋을 만든다. 두 커밋을 비교하고 모든 변경을
   한 그룹으로 합쳐 Flow/Class/코드 관계도 3종을 3회 생성한다.
   Git 설치·사내 정책은 기존 설치 안내를 따른다.
3. results.csv에 각 실행의 최종 상태, 전체 완료 시간, 실제 전송 수, 검토 완료/전체 단위,
   페이지 수와 동작·근거 확인 결과를 기록한다. 작업 진단 다운로드를 함께 보관한다.
   5분 경고는 중단이 아니다. 기본 900초 후 부분 결과와 이어하기도 별도 확인한다.
4. 합성 응답 회귀 기준: 코드 Flow 10회/41페이지, 코드 3종 14회/43페이지,
   Git 3종 30회/51페이지. 목표 요청 상한은 코드 20회, Git 32회다.
   실제 모델의 수정·재시도는 추가 요청을 발생시킬 수 있다. 300초 목표와 의미 품질은
   사내 PC 실측으로 판단하며 위 합성 요청 수를 실제 지연 시간으로 간주하지 않는다.
5. 코드 블럭의 동일 작업을 다시 생성해 완료 결과 재사용 시 추가 전송이 없는지 확인한다.
   별도 신규 작업의 생성 도중 취소하고 부분 결과를 열어 모든 정적 페이지와 검토된 설명을
   확인한다. 이어하기 후 검토된 요청 재사용 및 최종 페이지·원본 근거 보존을 확인한다.

진단에는 본문이 포함되지 않는다. 결과 CSV에도 코드·정책·실제 서버 주소를 적지 않는다.
