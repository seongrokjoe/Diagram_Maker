LLM 설정 예제 적용 안내 (0.1.0-perf.2)
====================================

같은 폴더의 llm-policy.example.json이 완성된 JSON 예제다.
Endpoint, AllowedOrigin, Model 세 값을 사내 승인 주소와 모델명으로 바꾸어
%LOCALAPPDATA%\DiagramMaker\llm-policy.json 에 저장하고 프로그램을 재시작한다.
llm.invalid 및 approved-model은 예시 값이다. 실제 서버 주소나 모델명으로 그대로 사용할 수 없다.
기존 승인 설정을 사용 중이면 해당 주소/모델명을 보존하고 아래 한도 값을 비교해 적용한다.

단위가 다른 세 가지 한도
-----------------------
MaxInputCharacters: 2000000 (문자 수)
  요청 문자열의 크기 제한이다. 60000은 60000토큰을 뜻하지 않는다.
  공유 의미 생성은 마스킹과 ID 치환을 끝낸 요청 JSON을 기준으로 검사한다.
  현재 여유분 3500자를 제외한 허용 길이는 1996500자다.
  60000으로 설정하면 허용 길이는 56500자이므로 수정/검토를 붙인 요청이 넘칠 수 있다.
  2000000으로 늘려도 아래 토큰 및 전체 문맥 검사는 계속 적용된다.

MaxInputTokens: 200000 (입력 토큰 수)
  사용자가 확인한 사내 LLM의 1회 입력 상한에 맞춘 값이다.
  토큰 수는 문자 수와 같지 않으며 모델의 토크나이저와 입력 내용에 따라 달라진다.

MaxContextTokens: 200000 (입력과 출력 예약을 합한 전체 문맥 토큰 수)
  예제는 앱의 기존 기본값인 200000을 유지한다. 사내 서버의 전체 문맥 한도가
  확인되지 않은 상태에서 입력 상한에 출력 토큰을 더해 이 값을 늘리지 않는다.
  서버의 전체 문맥 한도가 더 작으면 그 값에 맞춘다.
  실제 요청은 입력 토큰 + 요청 출력 예약 + 전송 계층 여유 1024토큰이 이 값 이하여야 한다.

공유 의미 묶음
-------------
코드 블럭/Git 공유 의미 생성은 기본 입력 48000토큰 이내의 묶음으로 나눈다.
이는 MaxInputCharacters=60000과 별개이며 출력과 후속 검토 요청 크기를 관리하기 위한 단위다.
Thinking OFF: 생성 출력 최대 8000, 검토 출력 최대 2000토큰.
Thinking ON: 출력 최대 60000토큰을 예약하며 전체 문맥 제한을 함께 적용한다.
서버/출력 설정이 더 작으면 그 상한을 우선한다. 원본 코드 근거는 임의로 자르지 않는다.
문자/토큰 한도를 통과해도 응답의 ID·항목·한국어 설명 또는 원본 의미 검토가 실패할 수 있다.

사내에서 확인할 내용
-------------------
화면의 '요청 오류 진단'에서 최초/후속 기록, 생성/검토/수정 단계, 실제 문자 수와 허용값,
응답 항목 수·누락·중복·알 수 없는 ID, 오류 코드를 확인한다.
진단의 입력 토큰은 서버 토큰 계산 결과 또는 보수적 추정치다.
실제 코드로 Thinking OFF 상태에서 전체 완료 시간과 의미 품질을 확인한다.
이 예제와 합성 검증은 사내 모델의 의미 품질이나 5분 완료를 보증하지 않는다.
