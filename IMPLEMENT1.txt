
  # 코드 블럭 다이어그램 UI·의미 생성 개선

  ## 1. 확정 방향

  - 사용 대상은 코드 문법에 익숙하지 않은 사용자다. 기본 그림에는 동작의 의미와 판단 결과를 쉬운 한국어로 표현하고, 원문
    은 근거 보기에서 제공한다.

  - 출력 설정은 그룹 단위로 공유한다. 블럭을 클릭하면 해당 코드와 소속 그룹의 출력 옵션을 함께 보여준다.
  - 화면은 코드 구성 / 다이어그램 결과로 전환한다.
  - 실제 사내 LLM 연결은 이번 검증 범위에서 제외한다. 합성 코드와 가상 LLM 응답으로 인터페이스·생성 흐름·실패 처리를 검
    증한다.

  - LLM 미설정·실패·의미 검토 실패는 완성 결과로 취급하지 않는다. 정적 구조는 별도로 열 수 있게 한다.

  ## 2. 입력·그룹·결과 화면 개편

  코드 구성 화면

  - 전체 블럭 목록, 그룹 목록, 선택 그룹의 블럭 목록을 연동한다. 선택·소속 그룹·구성원 수를 명확히 표시한다.
  - 블럭 클릭 시 소속 그룹과 구성원 목록이 함께 선택되고, 오른쪽에 제목·언어·코드·선택 설명을 통합한 편집기를 연다. 모든
    코드 입력창을 한꺼번에 펼치지 않는다.

  - 그룹 생성·이름 변경·병합·독립 분리를 제공한다. 블럭 이동은 드래그와 명시적인 ‘그룹으로 이동’ 메뉴를 모두 지원한다.
    이동·추가·삭제로 다른 그룹의 출력 설정이 초기화되지 않도록 한다.

  - 출력 종류는 ‘종류 추가’ 드롭다운으로 선택한다. 기존의 그룹당 최대 5종과 자동 추천을 유지하되, 선택한 출력의 프리셋·
    상세도·보완 요청만 표시한다.

  - 옵션 영역에 “이 그룹의 블럭 N개에 적용”을 표시하여 블럭별 설정으로 오해하지 않게 한다.

  다이어그램 결과 화면

  - 왼쪽에는 다이어그램 종류 → 그룹 → 요약/상세 페이지 트리, 오른쪽에는 선택한 그림을 크게 배치한다.
  - 페이지 선택용 버튼 나열을 제거하고, 트리의 선택·펼침·키보드 탐색을 지원한다.
  - 확대·맞춤 보기·편집·다운로드는 캔버스 도구 모음에 모은다. 동작 설명과 원본 근거는 필요할 때 여는 보조 영역으로 배치
    한다.

  - 생성 이력은 별도 선택기로 관리한다. 새로고침과 화면 전환 후 선택한 작업·결과 위치를 복원한다.
  - 단일 함수에서 요약과 상세가 동일하면 중복 페이지를 만들지 않는다.
  - 실패 항목과 정적 구조는 완성 결과와 구분한다. 재생성 실패 시 이전 성공 그림은 유지하고 최신 실패 사유를 표시한다.

  ## 3. 의미 중심 생성과 차단 오류 수정

  사내 LLM 인터페이스 개선

  기존 전송 인터페이스는 재사용하되, 코드 블럭 전용 계획·검증을 강화한다.

  1. 파서가 조건, 호출, 대입, 반환, 반복과 원본 위치를 추출한다.
  2. LLM에 함수 전체 문맥과 관련 블럭, 사용자 설명, 출처가 구분된 관계를 전달한다.
  3. LLM은 문장별 라벨 대신 의미 단계·자연어 조건·처리 결과·근거 참조를 구조화된 응답으로 반환한다.
  4. 같은 분기 안의 연속 처리는 하나의 의미 단계로 묶을 수 있게 한다. 예를 들어 상태 코드 지정·오류 응답 작성·반환은 “접
     근 거부 응답을 보내고 종료”로 표현한다.

  5. 검증기는 분기 방향, 반복, 조기 종료, 호출 근거와 요약된 코드 범위를 확인한다. 분기나 함수 경계를 넘어 순서를 만들어
     내는 요약은 거부한다.

  6. 의미 검토 후 최대 한 번 수정한다. 실패하면 원인과 정적 구조를 별도로 제공한다.

  공통 Git 생성 규칙을 일괄 완화하지 않고 코드 블럭 전용 검증으로 구현한다. 제공되지 않은 함수 본문이나 업무 의미는 추측
  으로 확정하지 않는다.

  하지 않는다.

  미리보기 차단 오류

  현재 MermaidPreview.tsx는 전체 DSL에서 URL을 검색하여, 예제의 http://localhost:5173이 라벨에 들어가도 차단한다.

  - 표시용 문자열과 실행 가능한 Mermaid 구문을 구분하도록 검사한다.
  - URL·click 같은 단어가 일반 텍스트에 들어가면 안전하게 표시한다.
  - 실제 링크 동작, click 명령, 설정 지시문과 삽입 구문은 계속 차단한다. Mermaid strict 설정과 SVG 정제도 유지한다.
  - 차단·문법 오류·LLM 실패를 서로 다른 메시지로 안내한다.
  - 후보 질문이 없는 단일 블럭에서 질문 개수 제한 경고가 발생하는 문제도 수정한다.

  ## 4. 계약·호환성과 검증

  - 기존 그룹별 출력 설정과 API 경로는 유지한다. 페이지의 요약/상세 구분, 대상 블럭·함수, 생성 실패 단계와 정적 결과 구
    분에 필요한 선택 필드만 추가한다.

  - 기존 작업·생성 결과·편집 이력을 계속 읽을 수 있게 한다. 이전 정적 결과는 새 화면에서 정적 구조로 분류한다.
  - 의미 계획·프롬프트 버전을 갱신하여 이전 결과 캐시를 새 품질 결과로 재사용하지 않는다.
  - LLM 구성 여부는 화면에서 확인할 수 있게 하되, 연결 주소나 인증 정보를 노출하지 않는다.
  - 가상 LLM은 테스트 환경에서만 사용하며, 운영 환경의 자동 대체 모델로 연결하지 않는다.

  - GuardAsync의 정상·샘플 차단·출처 차단·개발 환경 예외·본문 제한 변경 불가 경로가 모두 보존된다.
  - 기본 그림에 원래 조건식, return;, 의미 없는 “데이터 처리”가 남지 않는다.
  - 모든 의미 단계에서 해당 원본 코드로 이동할 수 있다.
  - 합성 C/C++·C# 사례로 반복·조기 반환·오류 처리·블럭 간 호출을 검사한다.
  - 가상 응답의 근거 누락·분기 반전·허위 관계·잘못된 구조·시간 초과를 검증한다. 정상 응답 하나만으로 통과시키지 않는다.
  - URL을 포함하는 일반 라벨은 5종에서 렌더링되고, 실제 Mermaid 삽입은 차단된다.
