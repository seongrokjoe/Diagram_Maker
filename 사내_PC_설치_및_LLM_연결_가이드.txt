Diagram Maker 사내 PC 오프라인 설치 및 LLM 연결 가이드
=========================================================

1. 권장 설치 방식
---------------------------------------------------------

사내 PC가 registry.npmjs.org에 접근할 수 없다면 GitHub의 일반 Source code ZIP이 아니라
Releases 화면의 다음 완성 실행 패키지를 내려받는다.

  DiagramMaker-0.1.0-offline.1-win-x64.zip
  DiagramMaker-0.1.0-offline.1-win-x64.zip.sha256

완성 패키지는 다음 항목을 이미 포함한다.

- Windows x64용 self-contained .NET 애플리케이션
- Windows x64용 portable Node.js 24
- Git Worker 운영 의존성
- 빌드된 React/Mermaid 웹 화면

따라서 사내 PC에는 .NET SDK, Node.js, npm, PowerShell 및 외부 npm 접속이 필요하지 않다.


2. 무결성 확인과 압축 해제
---------------------------------------------------------

CMD에서 실행한다.

  certutil -hashfile DiagramMaker-0.1.0-offline.1-win-x64.zip SHA256

출력된 값이 .sha256 파일의 값과 정확히 같은지 확인한다.
ZIP은 C:\Tools\DiagramMaker처럼 사용자가 쓰기 가능한 로컬 폴더에 압축 해제한다.
OneDrive 동기화 폴더와 네트워크 공유 폴더는 가급적 사용하지 않는다.


3. 사내 LLM 정책 설정
---------------------------------------------------------

압축을 푼 폴더에서 다음 파일을 실행한다.

  configure-llm.cmd

메모장에 열린 정책 파일에서 다음 값만 실제 승인 값으로 바꾼다.

  Endpoint      /v1/chat/completions까지 포함한 전체 URL
  AllowedOrigin scheme + host + port
  Model         승인된 모델명

예시 구조:

{
  "Llm": {
    "Enabled": true,
    "AllowDevelopmentStub": false,
    "Endpoint": "https://llm.invalid/v1/chat/completions",
    "AllowedOrigin": "https://llm.invalid",
    "Model": "approved-model",
    "ConnectTimeoutSeconds": 120,
    "NoResponseTimeoutSeconds": 120,
    "RequestTimeoutSeconds": 300,
    "DiagramOutputTokens": 16000,
    "ReviewOutputTokens": 8000,
    "OutputHardLimit": 60000,
    "MaxInputCharacters": 60000,
    "MaxTransientRetries": 1
  }
}

Endpoint와 AllowedOrigin의 scheme, host, effective port가 정확히 같아야 한다.
현재 사내 vLLM 계약은 Authorization/API Key를 사용하지 않는다.
실제 endpoint와 모델은 Git 저장소나 GitHub 이슈에 올리지 않는다.


4. 네트워크와 인증서 사전 확인
---------------------------------------------------------

사내 LLM host를 이용해 CMD에서 확인한다.

  nslookup 사내-llm-host
  curl.exe -I https://사내-llm-host

TLS 인증서 오류가 발생하면 인증서 검증을 끄지 말고 Windows 신뢰 저장소에 사내 루트 CA가
정상 설치됐는지 확인한다. 앱은 proxy, redirect, cookie, 기본 Windows 자격 증명과 TLS 검증
우회를 사용하지 않는다.


5. 애플리케이션 실행
---------------------------------------------------------

  start.cmd

정상 실행되면 다음 주소에서 요청을 기다린다.

  http://127.0.0.1:5080

Now listening 메시지 이후 멈춘 것처럼 보이는 것은 정상이다. CMD 창을 닫지 않는다.


6. 앱 상태와 실제 LLM 계약 시험
---------------------------------------------------------

새 CMD 창에서 설치 폴더로 이동한 뒤 실행한다.

  health-check.cmd
  test-llm.cmd

test-llm.cmd는 실제 프로젝트 데이터 대신 고정 synthetic 데이터만 사용해 다음을 확인한다.

1) DNS/TCP/TLS/HTTP와 기본 completion 응답
2) structured_outputs.json 기반 DiagramIR 응답
3) chat_template_kwargs.enable_thinking=true 기반 Thinking 응답

결과에는 성공 여부, 응답 시간, finish_reason, 노드/엣지 수만 표시한다.
모델 응답 원문이나 reasoning_content는 로그와 시험 결과에 저장하지 않는다.


7. 브라우저 사용
---------------------------------------------------------

브라우저에서 다음 주소를 연다.

  http://localhost:5080

사내 LLM 점검:

1) "사내 LLM 점검" 탭 선택
2) 기본 연결 시험
3) DiagramIR 계약 시험
4) Thinking 계약 시험

자연어 다이어그램:

1) "자연어 다이어그램" 탭 선택
2) 요청별로 "Thinking 모드 사용" 선택 또는 해제
3) 다이어그램 생성

Git 변경 분석:

1) "저장소 관리"에서 로컬 저장소 루트 또는 .git 절대 경로 입력
2) 연결 테스트 후 등록
3) "Git 변경 분석"에서 Base=HEAD~1, Target=HEAD 입력
4) "사내 LLM 변경 요약 포함" 선택
5) 필요하면 "Thinking 모드 사용" 선택
6) 분석 시작

Thinking은 요청별 선택이며 기본값은 해제이다. Git LLM 요약을 해제하면 Thinking도 자동으로
비활성화된다.


8. 종료
---------------------------------------------------------

start.cmd가 실행 중인 CMD 창에서 Ctrl+C를 누른다.


9. 오류 분류
---------------------------------------------------------

LLM_ENDPOINT_OUTSIDE_ORIGIN 또는 origin 관련 시작 오류:

- Endpoint와 AllowedOrigin의 scheme, host, port 확인
- AllowedOrigin에 path나 query를 넣지 않았는지 확인

LLM_TRANSPORT:

- DNS, 방화벽, direct 연결 경로 확인
- 앱은 시스템 proxy를 사용하지 않음

LLM_REQUEST_TIMEOUT / LLM_NO_RESPONSE_TIMEOUT:

- 서버 첫 응답 지연과 모델 로딩 상태 확인
- RequestTimeoutSeconds와 NoResponseTimeoutSeconds 구분

LLM_HTTP_400/404/422/501:

- endpoint path와 structured_outputs 지원 확인
- 구조화 기능 미지원 상태는 schema 제거 fallback을 한 번 수행함

LLM_RESPONSE_FORMAT / LLM_SCHEMA_INVALID:

- choices[0].message.content 문자열 형식 확인
- content가 설명과 섞이지 않은 JSON 객체인지 확인
- reasoning_content가 아니라 content에 최종 JSON이 들어오는지 확인

LLM_RESPONSE_TRUNCATED:

- finish_reason=length가 반환된 상태
- 출력 token 한도와 응답 크기 확인

로그는 start.cmd를 실행한 CMD 창에 안전한 요청 메타데이터만 표시하며 파일로 자동 저장하지 않는다.
endpoint, prompt, Git 소스, response body와 reasoning 원문은 출력하지 않는다.


10. Source code ZIP을 사용하는 경우
---------------------------------------------------------

Source code ZIP은 node_modules를 포함하지 않는다. 외부 npm이 차단된 사내 PC에서
npm ci를 실행하면 registry.npmjs.org 접속 오류가 발생한다.

개발 목적이 아니라 실행 목적이면 Source code ZIP 대신 완성 실행 패키지를 사용한다.
개발 목적으로 소스를 빌드하려면 승인된 사내 npm/NuGet 저장소가 별도로 필요하다.
