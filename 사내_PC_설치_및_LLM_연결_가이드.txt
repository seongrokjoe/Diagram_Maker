Diagram Maker 사내 PC 오프라인 설치 및 LLM 연결 가이드
=========================================================

배포 버전: 0.1.0-internal.4
검증 결과: SECURITY_AUDIT_REPORT.md

1. 패키지 준비와 무결성 확인
---------------------------------------------------------

저장소의 artifacts\release 폴더에서 다음 두 파일을 받는다.

  DiagramMaker-0.1.0-internal.4-win-x64.zip
  DiagramMaker-0.1.0-internal.4-win-x64.zip.sha256

CMD에서 해시를 계산하고 .sha256 파일의 값과 비교한다.

  certutil -hashfile DiagramMaker-0.1.0-internal.4-win-x64.zip SHA256

ZIP을 C:\Tools\DiagramMaker 같은 쓰기 가능한 비동기화 로컬 폴더에 완전히 압축 해제한다.
OneDrive, 네트워크 공유, 링크·정션 경로는 사용할 수 없다.
기존 설치의 데이터가 필요하면 앱을 종료하고 사내 보존 정책에 따라 백업한다.

패키지는 자체 포함 .NET 실행 파일, Windows x64 Node.js, Git Worker와 React/Mermaid 화면을
포함한다. 실행 PC에서 .NET SDK, Node.js/npm 설치나 공개 패키지 다운로드는 필요하지 않다.
Git 변경 분석에는 사내 승인 Git을 권장하며 CMD에서 git --version으로 확인한다.

2. 기본 실행: LLM 설정만 준비
---------------------------------------------------------

  configure-llm.cmd

메모장에 열린 %LOCALAPPDATA%\DiagramMaker\llm-policy.json에서 승인된 값을 설정한다.

  Endpoint      : /v1/chat/completions까지 포함한 전체 URL
  AllowedOrigin : scheme + host + port
  Model         : 승인된 모델명

Endpoint와 AllowedOrigin의 scheme, host, 실제 port가 일치해야 한다.
현재 LLM 계약에는 Authorization/API Key를 사용하지 않는다.
실제 endpoint·모델 설정과 사용자 코드는 Git이나 공개 이슈에 올리지 않는다.

  start.cmd

기본 실행에는 별도 network-policy.json이나 IP/경로 허용목록이 필요하지 않다.
이전 설치의 기본 위치에 network-policy.json이 남아 있어도 자동으로 읽지 않는다.
정상 실행 주소는 http://127.0.0.1:5080 이며 CMD 창을 닫지 않는다.

3. 관리자 선택 사항: 별도 허용목록 적용
---------------------------------------------------------

관리자가 연결 origin·IP·로컬 폴더를 추가 제한할 때만 아래 절차를 사용한다.

  configure-network.cmd

LocalRoots에는 배포·데이터·저장소·LLM 설정 폴더의 비동기화 절대 경로를 등록한다.
LlmOrigins에는 승인된 scheme/host/port, LlmAddressRanges에는 해당 IP CIDR을 등록한다.
PostgreSQL을 사용할 경우 Databases에 승인된 리터럴 IP와 포트를 등록한다.

  start-with-network-policy.cmd

이 실행기는 기본 위치의 network-policy.json을 명시적으로 적용한다.
다른 정책은 DIAGRAMMAKER_NETWORK_POLICY_PATH에 절대 경로를 지정한다.
이 환경변수가 설정돼 있으면 일반 start.cmd와 개발·빌드에도 해당 정책을 적용한다.
파일 누락·JSON 오류·빈 허용목록·허용되지 않은 경로/주소는 실행 또는 연결을 거부한다.
오류가 나도 자동으로 기본 모드로 바뀌지 않는다.
기본 모드로 돌아갈 때는 해당 환경변수를 해제하고 start.cmd를 사용한다.

두 모드 모두 origin 검증, TLS 검증, 프록시·리디렉션 차단, 비동기화 경로와 Git 보호를 유지한다.
기본 모드에서는 IP 허용목록으로 내부 주소를 판별하지 않으므로 승인된 사내 설정을 사용한다.
호스트 방화벽·내부 DNS·정책 파일 ACL은 사내 운영 절차에 따라 관리한다.

4. 연결 검사와 기능 시험
---------------------------------------------------------

새 CMD에서 설치 폴더로 이동해 실행한다.

  health-check.cmd
  test-llm.cmd

고정 합성 데이터로 기본 연결, DiagramIR 구조, Thinking 계약을 점검한다.
모델의 원문 응답이나 reasoning_content를 시험 결과에 저장하지 않는다.
TLS 오류는 Windows 신뢰 저장소의 사내 CA 설정으로 해결하고 검증을 끄지 않는다.

브라우저에서 http://127.0.0.1:5080 을 연다.

- 코드 블럭 다이어그램: 작업 제목과 합성 C/C++·C# 코드를 입력하고 그룹별 종류를 선택해 생성한다.
  의미 설명 완료 여부, 조건·반복·반환, 블럭 간 호출, 각 단계의 원본 근거를 확인한다.
  저장·새로고침·결과 편집·SVG/PNG 다운로드도 점검한다.
- Git 변경 분석: 저장소 관리에서 로컬 저장소를 등록하고 Target 커밋, 변경 심볼과 그룹을 선택해 생성한다.
- 자연어 다이어그램과 LLM 점검: 해당 메뉴에서 요청별 종류·Thinking 설정과 계약 검사를 사용한다.

합성 연결 검사의 통과만으로 실제 모델의 코드 해석 품질을 판정하지 않는다.
LocalFile은 단일 앱 인스턴스용이며 공유 PostgreSQL은 별도의 실연결 검증이 필요하다.

5. 종료와 오류 확인
---------------------------------------------------------

앱을 실행한 CMD에서 Ctrl+C를 누른다.

시작 실패: 비동기화 경로, LLM 설정 파일, Endpoint/AllowedOrigin 일치를 확인한다.
선택 정책 오류: DIAGRAMMAKER_NETWORK_POLICY_PATH와 JSON 내용, LocalRoots 및 IP 목록을 확인한다.
연결 실패: 사내 DNS·방화벽·인증서·실제 모델명을 확인한다.
의미 설명 미완료: 화면의 고정 진단과 원본 근거를 확인한 뒤 입력/모델 설정을 보완한다.

상세 기능은 README.md, 데이터 보존·권한 정책은 SECURITY.md를 참조한다.
